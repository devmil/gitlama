# Changelog

## Unreleased Stable

- Revert over local changes instead of requiring a clean worktree. The preview compares the local changes with the paths the reverted commits change (devmil-git `probes::changed_paths` and `merge::local_changes::local_change_overlap`). Changes that are neither staged nor collide stay in place and Git reverts around them. Colliding or staged changes are listed in the review, and confirming "Set aside and revert" saves them in a marked stash (`GitLama before revert …`), reverts on the clean worktree and reapplies them with `stash apply --index`, falling back to a plain apply so conflicts reach the conflict resolver as a stash reapply. When the revert itself stops at conflicts, a per-worktree marker in `.git/gitlama/set-aside` keeps the changes aside until the revert is continued or aborted from the resolver, which then reapplies them; a continuation whose reapply conflicts now reports Conflict instead of Completed. The stash stays in Stashes as a recovery copy, as with protected pull, whose stash handling now shares the same `stash_handoff` module. A preview turns stale when the local changes collide differently at execution. Apply-only reverts keep local changes only in place and otherwise fail with the new `localChangesOverlap` code. Only unresolved conflicts still disable Revert. This raises the remote helper to version 23, so hosts receive a new helper.
- Link GitLama's public source repository. About has a "Source code on GitHub" button that opens `https://github.com/devmil/gitlama` through the release-index repository (`openSource`, a fixed URL like the issue tracker), and the website links it from the header (hidden below 620 px) and from the footer of every page. The remote helper keeps version 22.
- Remove repository undo and redo ([ADR 0005](docs/adr/0005-no-repository-undo.md)). The undo ledger (`undo.rs`, `.git/gitlama/undo`), Recovery history, the Undo and Redo commands with their Ctrl+Z/Cmd+Z and Ctrl+Y/Cmd+Shift+Z shortcuts, the `repository_session_undo_*` bridge calls and the remote `Undo` write family are gone, and no review says "You can undo this" any more. It covered only some actions, and the stash apply/pop and snapshot restore reviews promised undo the ledger never recorded. Destructive reviews now state the loss instead (Discard and Clean delete permanently, a hard reset loses the discarded changes, deleting on a remote may already have been fetched). Restoring a named snapshot over local changes now keeps them as a visible stash ("Changes before restoring a snapshot") instead of only a hidden ref. A mutation is no longer reconciled with a warning because recording its recovery anchor failed. Stored shortcut overrides for the removed commands are dropped when settings load, and older pending remote writes of the `Undo` family when the pending store loads; ledgers earlier versions wrote stay on disk unread. UND-01 is withdrawn, and the QSpline command parity audit records Undo and Redo as withdrawn. This raises the remote helper to version 12, so hosts receive a new helper.
- Remember how diffs are shown. Wrap long lines, the unified or side-by-side layout, whitespace handling, context lines, plus/minus markers and the minimap are now one stored choice (`appearance.diff*` in the settings document) shared by the Changes diff, the History inspector and the conflict resolver's comparison, which now follows the shared wrap choice instead of always starting wrapped. The diff toolbars and the new Diffs page in Settings change the same values; Show more context still widens only the diff on screen. Inspector windows start with the stored choice and keep their own changes while open. The remote helper keeps version 11.
- Add Save snapshot as ZIP… to the History commit menu, the History command menu and the commit summary card. devmil-git `archive::write_commit_zip` builds the zip from the commit's tree (`ls-tree -r` and one `cat-file --batch`), not `git archive`, so export rules do not apply: modes and symbolic links are kept, everything sits under `<repository>-<short hash>/`, submodules are included at their recorded commits when their repository is available locally, and LFS pointers become their content from the local store or `git lfs smudge`. What cannot be resolved stays an empty folder or a pointer and is counted in the result. The zip is built in the background into a private temporary file on the computer that holds the repository (new `repository_session_archive_*` read-surface calls, the page call on the bulk queue) and copied in 1 MiB pages into a part file beside the chosen destination, which replaces it once complete; Cancel stops both. This raises the remote helper to version 11, so hosts receive a new helper.
- Add "Add to .gitignore…" to the menus of unstaged files and folders. The dialog prefills the top-level entry that matches exactly the path (devmil-git `ignore::exact_pattern`: anchored with `/`, wildcards and trailing spaces escaped, `/` for a folder) and appends the edited entry to the worktree's top-level `.gitignore` through a new `ignoreAdd` extension mutation: atomically, keeping CRLF files CRLF, without duplicating a line that is already there, and never through a linked `.gitignore`. Tracked files say that the entry hides them only once they are untracked. Repositories on another computer use the host's extension writes. This raises the remote helper to version 10, so hosts receive a new helper.
- Build the settings window on Meridian's shared settings dialog (1.14.0): it is 840 px wide so every settings row keeps its label beside the control, keeps its height while you switch pages, and keeps the page list down to narrow windows, switching to a page menu only when the dialog is narrower than 600 px.
- Use the rounded desktop icon (brand `40247f2`) for the Linux packages, the Windows icon and the macOS icon catalog, and the rounded tile for the app icon on the launch, welcome and About screens. Ship the desktop entry and icon in the portable Linux tar.
- Use the same diff viewing controls in Changes and History, including split layout, context, whitespace, wrapping, indicators, minimap and encoding.
- Show a failed action in a dialog instead of a banner pinned to the top of the window. It keeps the message, the command line and output of the Git command that failed (collapsed under Git output), and Copy support report; an opt-in checkbox appends the Git output to the report, which otherwise still holds only typed facts. Transfer reports now name the failure code (`transfer.*`) and the activity number. A failure while the dialog is open replaces its content, so failures never stack.
- Explain failed fetches, pulls and pushes from one failure catalog. devmil-git's new `diagnosis` table recognises host-key, missing-object, authentication, lock-conflict, stale-lease and remote-ahead failures (transfer classification now reads the same table) and names the ref a lock conflict is about; GitLama maps each diagnosis to an explanation and remedies in one dialog, and the support report adds `Diagnosis: <kind>`.
- Lock conflicts ("Unable to create '….lock': File exists") list the repository's lock files (index, `HEAD`, `packed-refs`, `config` and loose-ref locks, via devmil-git `git_locks`) with their age, say whether they look in use or left behind, and offer Try again, Check again, Remove locks and try again, and for a pruning fetch Fetch without pruning. Each lock is removed only while it is still the inspected file and never while GitLama itself is changing the repository; locks of a repository on another computer are listed but not removed.
- A lock conflict on a ref that has another spelling differing only in letter case (from the repository's refs or the refs the fetch reported) is a case collision: on case-insensitive file systems such as macOS both share one loose-ref file, so `fetch --prune` fails on its own lock. The dialog names both spellings and offers Repair and fetch again, which deletes the local remote-tracking refs (each only while unchanged) and fetches again, or Fetch without pruning.
- A push rejected as non-fast-forward or "fetch first" explains that the remote has newer commits and offers Fetch.
- Add a "Remove remote branches deleted on the server" option to the Fetch dialog (on by default, as before); turning it off runs `git fetch` without `--prune`.
- A restarted host no longer makes its open repositories report a different identity. The remote helper bound each repository to its filesystem's device number, which btrfs (Fedora's default) assigns anew at each mount; it now uses the filesystem ID (`statvfs` `f_fsid`) with the inode, so the binding, write receipts and write locks survive a restart. A repository that really changed under a host that still matches now says so in its tab and offers Trust and open, which forgets the old binding and reopens it; before, the tab sent you to the host dialog, which had nothing to decide.
