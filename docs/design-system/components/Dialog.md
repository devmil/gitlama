# Dialog

A modal question. Use it only when the answer is needed before Git can go on: confirming a destructive step, or choosing options for merge, rebase, reset or force push. It takes `title` (the full command with real names), `description` (the consequence, in numbers), `children` (a before/after preview such as the `ns-flow` strip, or options), `aside` (option checkboxes, bottom left) and `actions` (Cancel on the left, the primary verb on the right).

`raised`, `radius-xl`, `shadow-float`, `space-7` padding, on `scrim`. Enter runs the primary action. Escape cancels. For destructive verbs, primary becomes `danger` and focus starts on Cancel.

In GitLama:

- **Confirmations use `showMeridianConfirm`.** The primary button carries the verb ("Delete", "Drop stash", "Restore file"), never "OK", "Confirm" or "Continue"; Cancel is `context.l10n.cancel`. Plain text goes in `description`; lists, command previews and flow strips go in `content`. `scripts/check_meridian_usage.py` rejects a hand-built `MeridianDialog` whose actions are only Cancel and one button around plain text (`hand-built-confirmation`). A confirmation that needs state (an acknowledgement checkbox, a typed word) stays a `MeridianDialog` with `onSubmit` and `submitDisabled`, and focuses Cancel when it is destructive.
- **Information and management dialogs close with ✕.** A dialog that asks nothing (details, a reference, About, a list to manage such as Hosts) passes `onClose` to `MeridianDialog` and keeps only real commands ("Add host…") in `actions`; it never has a footer Close button. Questions end with Cancel and the verb and never take `onClose`.
- **Scrim:** a click on the scrim cancels a confirmation, which is always safe, including destructive ones. Only questions that must be answered explicitly turn it off (`barrierDismissible: false`): trusting a host key, entering credentials, authorizing a hosting request, and approving an external program's command line.
- **Widths by kind:** `MeridianLayout.dialogConfirmWidth` (460) for confirmations and short information, `dialogFormWidth` (560) for forms and pickers, `dialogWorkflowWidth` (760) for workflows, editors, browsers and settings. Special surfaces (the command palette, repository details, the full-window review) size themselves.
- **Enter:** every form passes its primary action as `onSubmit` with the button's validity as `submitDisabled`, so Enter in a single-line field submits or shakes. A dialog on its own `MeridianDialogSurface` with a primary action wraps its fields in `MeridianDialogSubmitScope`.
- **Forms put labels above fields** (`MeridianTextField(label: …)`, `GitReferenceField(label: …)`), in a `Column(crossAxisAlignment: stretch, spacing: MeridianSpace.space6)`. Side-labelled `MeridianSettingsGroup` rows belong to Settings, not dialogs. Options are `MeridianCheckbox`es aligned with the fields' leading edge; give an option a `description` when its effect is not obvious from the label.
- **Speak the user's language.** The title names the action, `description` says in one sentence what happens. Prefer "new files" to "untracked files" and "staged" to "index" unless the Git term is the point. Git commands go behind `GitCommandDetails`.
- **Facts are a `MeridianPropertyList`**, not a stack of `Text` lines: what changes, how many files, which branch. Recovery and caveats follow as one muted caption; warnings are a `MeridianBanner`.
- **Lists are bounded and styled like the app's lists.** A list of files, commits, remotes or steps sits on a `paneAlt` well (`radius.lg`) with a `GitLamaLayout` max height and `MeridianListRow`s (checklists set `checked`). Files show the status glyph, the name and the muted folder. Never nest a `Flexible` or a second scroll view inside the dialog body, which already scrolls.
- **Spacing comes from tokens.** `space6` between sections, `space4` inside a group; no literal numbers.
