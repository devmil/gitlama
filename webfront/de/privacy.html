2. Überblick

Diese Website und GitLama sind so gebaut, dass so wenig Daten wie möglich anfallen. Devmil Solutions betreibt keine Analyse, keine Werbung und kein Tracking. Die Website setzt keine Cookies und lädt nichts von Servern Dritter: Skripte, Stile, Schriften und Bilder kommen von dieser Website. GitLama sendet Ihre Repositories, Zugangsdaten oder Nutzungsdaten nicht an Devmil Solutions.

3. Hosting

Die Website wird bei GitHub Pages gehostet (GitHub, Inc., 88 Colin P. Kelly Jr. Street, San Francisco, CA 94107, USA). Beim Besuch der Website verarbeitet GitHub technische Zugriffsdaten, um sie auszuliefern und abzusichern: IP-Adresse, Datum und Uhrzeit, aufgerufene Seite, Referrer, Browser und Betriebssystem. Rechtsgrundlage: Art. 6 Abs. 1 lit. f DSGVO (berechtigtes Interesse an einer sicheren und zuverlässigen Website).

GitHub kann Daten in den USA verarbeiten. GitHub, Inc. ist nach dem EU-U.S. Data Privacy Framework zertifiziert (Angemessenheitsbeschluss, Art. 45 DSGVO). Einzelheiten: Datenschutzerklärung von GitHub. Devmil Solutions hat keinen Zugriff auf diese Protokolle.

4. Downloads und Release-Daten

Die Download-Links und Versionshinweise auf dieser Website stammen aus einem statischen, signierten Release-Index, der von dieser Website ausgeliefert wird. Die Installationspakete selbst werden von GitHub Releases (github.com) heruntergeladen; GitHub kann den Download an eigene Dateiserver wie objects.githubusercontent.com weiterleiten. GitHub verarbeitet dabei dieselben technischen Zugriffsdaten wie unter Hosting beschrieben, auf derselben Rechtsgrundlage und gemäß der Datenschutzerklärung von GitHub.

5. Lokaler Speicher im Browser

Die Website speichert einen Wert im lokalen Speicher (Local Storage) Ihres Browsers: die gewählte Sprache (preferred-language, en oder de). Andere Seiten von Devmil Solutions auf devmil.de nutzen denselben Wert, damit sie in derselben Sprache öffnen. Der Wert bleibt auf Ihrem Gerät, wird nie übertragen und kann jederzeit im Browser gelöscht werden. Rechtsgrundlage: § 25 Abs. 2 Nr. 2 TDDDG (unbedingt erforderlich für einen von Ihnen gewünschten Dienst).

6. Die App

GitLama arbeitet mit den Repositories und Hosting-Konten, die Sie auswählen. Repository-Inhalte und Zugangsdaten werden nicht an Devmil Solutions gesendet. GitLama enthält keine Analyse, keine Absturzberichte und keine Telemetrie. Release-Versionen schreiben keine Protokolldatei; aus Diagnosemeldungen werden URLs, E-Mail-Adressen, Pfade und Geheimnisse entfernt, Zugangsdaten erscheinen darin nie.

Git-Remotes

GitLama nutzt das auf Ihrem Computer installierte Git. Clone, Fetch, Pull und Push sowie Git LFS und Submodule verbinden sich mit den Servern, die in Ihren Repositories als Remotes eingetragen sind, mit Ihrer eigenen Git-Konfiguration, Ihren Credential-Helpern und Ihrer SSH-Einrichtung. Standardmäßig rufen geöffnete Repositories alle 10 Minuten ihre Remotes ab (Fetch); ein Abruf, der eine Anmeldung bräuchte, wird übersprungen. Sie können das in den Einstellungen unter „Automatisch abrufen“ abschalten. Trifft ein Clone auf einen noch unbekannten SSH-Host, fragt GitLama dessen Schlüssel ab, damit Sie ihn prüfen und ihm vertrauen können. Die Betreiber dieser Server verarbeiten Ihre Daten nach ihren eigenen Datenschutzbestimmungen.

Hosting-Anbieter

Sie können GitHub (auch GitHub Enterprise Server), GitLab (gitlab.com oder eine selbst betriebene Instanz), Forgejo oder Codeberg verbinden. GitLama spricht dann direkt von Ihrem Computer aus die API dieses Anbieters an, um Pull- bzw. Merge-Requests, Issues, Check-Status und Review-Threads zu lesen. Mit aktivierter „Hintergrundaktualisierung“ sucht GitLama außerdem Pull-Requests zu den Branches, die Sie ansehen. Reviews, Kommentare und erneute Check-Läufe werden erst gesendet, nachdem Sie eine Vorschau bestätigt haben. Devmil Solutions betreibt keinen Server dazwischen. Der gewählte Anbieter verarbeitet diese Anfragen nach seinen eigenen Bestimmungen, zum Beispiel der Datenschutzerklärung von GitHub, der Datenschutzerklärung von GitLab oder der Datenschutzerklärung von Codeberg; für einen selbst betriebenen Server ist dessen Betreiber verantwortlich.

Anmeldung

Bei GitHub nutzt GitLama die Geräteanmeldung: Sie bestätigen einen Code bei GitHub in Ihrem Browser. Bei GitLab, Forgejo und Codeberg melden Sie sich im Browser an (OAuth mit PKCE), und der Anbieter leitet zu einer Adresse auf Ihrem eigenen Computer (127.0.0.1) zurück, an der nur GitLama lauscht. Die OAuth-Anwendung registrieren Sie selbst beim Anbieter; GitLama enthält keine Client-ID und kein Geheimnis von Devmil. Alternativ kann GitLama die Anmeldung der GitHub CLI (gh) oder GitLab CLI (glab) verwenden; es liest deren Token dann bei Bedarf und kopiert es nicht.

Zugangsdaten

Tokens für Hosting-Verbindungen werden im Anmeldedatenspeicher Ihres Betriebssystems abgelegt: im macOS-Schlüsselbund, in der Windows-Anmeldeinformationsverwaltung oder im Secret Service unter Linux (zum Beispiel GNOME Keyring oder KWallet). Ein Git-Passwort oder -Token, das Sie in GitLama eingeben, wird für diesen einen Vorgang über eine temporäre Datei an Git übergeben, die nur Ihr Benutzerkonto lesen kann; sie wird danach überschrieben und gelöscht, gespeichert wird nichts. GitLama nutzt Ihre OpenSSH-Einrichtung und Ihren SSH-Agenten und speichert keine privaten Schlüssel. Host-Schlüssel, denen Sie in GitLama vertrauen, liegen in einer eigenen known_hosts-Datei im Profilordner.

Update-Prüfung

Unter macOS nutzt GitLama Sparkle. Sobald Sie zustimmen, prüft es etwa einmal täglich den Update-Feed https://devmil.de/gitlama/appcast.xml auf dieser Website; Sie können auch manuell prüfen. Ein Systemprofil wird nicht gesendet. Updates werden von GitHub Releases heruntergeladen und vor der Installation anhand einer Ed25519-Signatur geprüft. Unter Windows und Linux prüft GitLama nur, wenn Sie in den Einstellungen „Nach Updates suchen“ wählen. Es liest dann https://devmil.de/gitlama/_data/releases.json von dieser Website und kann die Versionshinweise in Ihrem Browser öffnen; heruntergeladen oder installiert wird nichts. Diese Anfragen erreichen GitHub Pages und GitHub Releases, die die unter Hosting und Downloads beschriebenen technischen Zugriffsdaten verarbeiten.

Autorenbilder (Gravatar)

Autorenbilder sind standardmäßig ausgeschaltet. Wenn Sie „Gravatar verwenden“ einschalten, lädt GitLama Bilder von gravatar.com (Automattic Inc.). Für jeden Commit-Autor sendet es einen SHA-256-Hash der E-Mail-Adresse, nicht die Adresse selbst. Die Bilder werden nur im Arbeitsspeicher gehalten. Siehe die Datenschutzerklärung von Automattic.

Remote-Arbeitsbereiche

Remote-Arbeitsbereiche sind experimentell und standardmäßig ausgeschaltet. Wenn Sie sie nutzen, verbindet sich GitLama mit dem ssh Ihres Systems zu Hosts aus Ihrer SSH-Konfiguration. Es fragt nie nach einem Passwort und akzeptiert nie unbekannte Host-Schlüssel. Nach Ihrer Bestätigung kopiert es ein kleines Hilfsprogramm auf diesen Host. Repository-Daten fließen nur zwischen Ihrem Computer und diesem Host.

Externe Werkzeuge

Editoren, Terminals, Diff- und Merge-Tools, Diff-Renderer und eigene Befehle laufen auf Ihrem Computer so, wie Sie sie eingerichtet haben. GitLama fügt ihnen keinen Netzwerkzugriff hinzu. Ein von Ihnen gewähltes Werkzeug kann sich selbst mit dem Netz verbinden; dafür gelten dessen eigene Bestimmungen.

Daten auf Ihrem Gerät

GitLama speichert Einstellungen und Zustand in einem Profilordner: ~/Library/Application Support/GitLama/ unter macOS, %APPDATA%\GitLama\ unter Windows und ~/.config/gitlama/ unter Linux. Darin liegen Ihre Einstellungen, die Pfade zuletzt geöffneter Repositories, Entwürfe für Commit-Nachrichten und Reviews, Werkzeugdefinitionen, Hosting-Verbindungen ohne deren Tokens sowie Caches. Zustand für Rückgängig und Wiederherstellung liegt im .git-Ordner des jeweiligen Repositorys. Wenn Sie diese Ordner und die Einträge im Anmeldedatenspeicher löschen, ist alles entfernt, was GitLama gespeichert hat.

Berechtigungen

GitLama fordert keine besonderen Berechtigungen wie Kamera, Mikrofon, Kontakte, Bildschirmaufnahme oder Mitteilungen an. Es arbeitet mit den Dateirechten Ihres Benutzerkontos. macOS kann um Erlaubnis fragen, wenn Sie ein Repository in einem geschützten Ordner wie Dokumente oder Schreibtisch öffnen oder wenn GitLama ein Token aus dem Schlüsselbund liest.
