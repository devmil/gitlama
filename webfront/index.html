Features

What it does

The everyday Git tasks, and some that usually mean a trip to the terminal.

Changes

Stage files, hunks or single lines. View diffs unified or split, including images and other encodings. Commit with amend, sign-off, templates and co-authors.

History

A history graph with file trees, blame and reflog. Compare two commits, search commit content and step through a bisect.

Branches and rewriting

Create, rename, merge, cherry-pick and revert. Interactive rebase, autosquash and restacking show a preview before they run.

Remotes and hosting

Fetch, pull and push, with force-with-lease as an explicit choice. Connect GitHub, GitLab, Forgejo or Codeberg for pull requests and review drafts.

Worktrees and tools

Manage worktrees, submodules and Git LFS. Open your editor, terminal, diff or merge tool, and add your own commands.

Recovery

Resume conflicts and rebases after a restart. Named snapshots and per-repository undo let you step back. When an outcome is unclear, the app says so.

The graph

Lanes that stay put

The branch you are on runs in the first lane. Other branches leave and rejoin it on curves, so a merge is easy to follow.

  • Selecting a commit lights its ancestors and dims the rest.
  • Branch, remote and tag labels sit on the commit they point to.
  • The command palette, shortcut hints and native menus work from the keyboard.

A model, not the app. Select a commit to light its ancestors.

Changes

Stage the lines you mean

Pick single lines from a diff and leave the rest unstaged. The same works for hunks and whole files.

  • Unified and split layouts, with whitespace and context controls.
  • The commit editor keeps a draft per worktree.

Remote workspaces

Work on repositories on another computer

Open a repository on a Linux machine, a Mac or a Raspberry Pi over the SSH you already use. Nothing is cloned: the repository stays where it is, and GitLama shows its history, changes and diffs as if it were on your desk.

  • Uses your SSH configuration, keys and agent. GitLama never asks for a password and never accepts an unknown host key.
  • Read only until you allow changes for a host. Then staging, commits, branches, stashes, fetch, pull and push run on that computer, with its own Git credentials.
  • Each host gets its own color and icon, so you always know which computer a tab belongs to.
  • A dropped connection comes back on its own, and a change is never sent twice.
